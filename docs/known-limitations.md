# Known limitations

[< Docs index](README.md)

- **CBR support is untested against real RAR files.** The code path exists and is exercised only with zip-backed `.cbr` files and a corrupt-file error case.
- **Whole-archive extraction for RAR.** Opening a `.cbr` extracts all of it to a temp folder, so large CBR batches are slower than CBZ.
- **Windows-only pieces:** Folder icons (`ctypes`, `desktop.ini`), the *Open folder* buttons (`os.startfile`). Explorer may need a refresh before new folder icons appear.
- **Filename parsing is heuristic.** Unusual names (e.g. titles with ` - ` before an issue number) can parse wrongly; the review tables exist for that reason.
- **Collected-edition detection is keyword based.** A series whose real title contains a format word (for example a series called *Deluxe*) is read as a collected edition; change its type on its card or in the Type column. A bare `Vol 3` is an issue unless you change **A name with only “Vol 3” is**. Series spelling is not unified beyond case and a leading *The*: `Walking Dead` and `Walking Dead Deluxe` are different series.
- **Renamer settings from before the revamp are not carried over.** The old naming style, custom template and collected-style choices are ignored; everything else of the page starts at its defaults, and the new per-type templates start at the old defaults.
- **Renamer details.** Hand edits on a card exist only until you rescan, rename or leave the app (nothing is saved between runs). The template box is narrow, so a long template scrolls inside it; the live example under it shows the result. `{publisher}` is empty unless ComicInfo.xml is used and has a publisher. A year is only recognised from 1900 to next year, and a year in the *middle* of the series name is not touched.
- **Series grouping from filenames** is a guess: it strips trailing issue/volume numbers and bracketed tags.
- **`ComicInfo.xml` rewrite** drops XML namespace declarations and appends new elements; field values and existing elements are kept.
- **`Archive` backups are renamed `.bak`, untested in YACReader.** Backups and converted `.cbr` files are stored as `<name>.cbz.bak` /
  `<name>.cbr.bak` so YACReader should not recognise them as comics. That is an inference, not a tested result. Backups made by earlier
  versions kept their real `.cbz` / `.cbr` names and may still be imported: add `.bak` to them by hand, or move those `Archive` folders out
  of your library. *Save all pages as ZIP* in Single issue also writes a `.zip`, which YACReader supports too.
- **Issue count is recognised only as "(of N)" / "(3 of 12)".** A bare "(3/12)" is not parsed, to avoid confusing it with dates. The
  Renamer reads the new fields but has no tokens for them.
- YACReader reads `ComicInfo.xml` **only if you enable it** (Settings > General) **and update the library** afterwards, so metadata written
  by the Metadata tool and the Library audit's fixes won't show until you do.
- **The scan's deep mode reads only each archive's first page**, so it can miss corruption deeper in a file; use the Library audit's full integrity test for that.
  Real RAR files are skipped unless **Open real .cbr files** (or `--deep-cbr`) is on. The cover-similarity levels (Strict 4, Normal 8, Loose 12 differing bits of 64)
  are untested on real covers (see [manual tests](manual-tests.md), C7 and D5).
- **Audit reports are heuristics.** Duplicates by series/issue depend on filename parsing; identical size can be a coincidence; covers from different editions
  of the same issue look alike (and variant covers may not). Missing-issue gaps assume numbering is continuous, so series with deliberate gaps (or issue #0, which is
  treated as not expected) will show false gaps. The warning limits (pages, size, cover height) are editable on the page but apply to every comic alike.
- **The audit holds its results in memory only.** Nothing is saved between runs except the scan cache, the settings and the ignore list; a very large library shows every row at once.
- **Reading orders in the audit.** Only the folders marked in Library stats are left out of Duplicates, so an unmarked folder of copies still shows as duplicates. Turning **Include reading orders in duplicates** on or off needs a rescan. The other checks (Missing, Junk, CBR) still look inside marked folders. The Details panel's pointer to Metadata opens the whole folder being audited, filtered to comics with no series or no issue number, not just the ones the audit counted.
- **Ignoring a Missing row hides everything it shows.** There is no way to ignore one number inside a row; a number that goes missing later still appears. A duplicate group is ignored by its exact set of files, so adding another copy brings it back.
- **Junk files are only found in zip-based comics.** A real RAR `.cbr` is not opened unless *Open real .cbr files* is on; fixing it converts it, which drops the junk.
- **Removing issue numbers is saved like any other edit.** The number is deleted from `ComicInfo.xml` (a `.bak` backup is kept unless you chose to replace) and the file name is untouched. Whether YACReader then really sorts by filename is untested (see [manual tests](manual-tests.md), B9 and E13).
- **The Metadata editor works on `.cbz` only.** A `.cbr` is listed but locked until converted. Suggestions come from the comics in the folder you opened (so open the whole library for library-wide suggestions), and a series name is matched ignoring case, punctuation and a leading *The*. Reading a very large folder takes a while because every comic's `ComicInfo.xml` is read; the table then loads as you scroll. The page is two columns that each keep a minimum width (about 420 and 480 px), so in a very narrow window it clips instead of reflowing. Edits exist only until you save or discard them (nothing is kept between runs), and the way of editing (*Automatic*, *One at a time*, *Several at once*) is not remembered.
- **Reading Order has no cover thumbnails,** and the whole list lives in memory only (no saved order file). It writes only CBZ (or zip-backed) files.
  Whether YACReader sorts the arc number numerically, and which of *Story arc* / *Alternate series* it shows best, is untested (see [manual tests](manual-tests.md), E).
  The filename-prefix recogniser (`01 - Name`, `[01] Name`) can misread a real name such as `100 - Bullets 05`.
- **ACEO sheets reads slots from rectangles.** A template must draw each card as a plain rectangle (`x y w h re`) on its first page, as the bundled one does; a template drawn with paths, images or rotated pages is not understood and is reported as having no card outlines. Pages are rendered as pictures (JPEG inside the PDF), so the PDF is print-sized and sharp at the chosen dpi but its text is not selectable. The bundled template's rows touch (cards share cut lines), which is how it is drawn. The preview is an approximation at 96 dpi. A portrait cover in a landscape slot is turned by default; if you would rather not, set **Turn the cover** to *Never turn*. The tool has not been test-printed.
- **Library stats groups by what the names and `ComicInfo.xml` say.** Series come from the filename (or ComicInfo) and are merged ignoring case, punctuation and a leading *The*, so `Walking Dead` and `Walking Dead Deluxe` stay separate series. *Publisher* exists only in `ComicInfo.xml`, so most libraries show a large *Unknown* publisher bar until the Metadata tool has set it. Real RAR `.cbr` files are not opened by the light scan: they count in every total but are left out of the ComicInfo.xml coverage figure. Page counts need **Read page counts** (first page only, as in the scan). The numbers on Home are a saved snapshot of the last scan and can be out of date until you Refresh; nothing watches the folder. Reading-order folders are only the ones you marked; the suggestion is a guess from numbered names or story arcs and can miss a folder or flag one that is not. The duplicate count on the Needs attention cards is a name-based estimate (same series, volume and issue), not the Library audit's full check.
- **Column widths are not remembered** between runs (the sidebar and options-panel widths are). An options panel cannot be made narrower than 270 px, because the wrapped hints in it are laid out for that width.
- **Two-column pages.** The width of the right column is saved (one value for the page, not one per folder) and the left column never gets narrower than about 400 px, so on a small window the right column cannot be dragged as wide as you asked. The Library audit's Details panel covers the Checks column while it is open. The pages not yet rebuilt (Folder icons, Reading order, ACEO sheets, the Renamer, Add to library) keep their options panel until their turn.
- **Choose comics keeps only what a tool can use** (CBR to CBZ takes `.cbr`, and so on), and the folder used for relative names is the nearest one containing the files that remain. After choosing comics, *Include subfolders* has no effect until you choose a folder again.
- **CBR to CBZ cannot count a RAR's pages up front.** The list shows whether a file is a real RAR or a zip with the wrong name, but not its page count, because counting means extracting it; the count appears in the log after the file is converted. A real RAR needs 7-Zip or unrar (the page says so for each file when neither is installed). The size warning compares the files to convert with the free space on the folder's drive and does not account for the original being kept. Converting is sequential, one file at a time.
- **Single issue shows five pages and one comic.** The strip is the cover, pages 2 and 3 and the last two (fewer in a short comic); every other page is reached through the Browse tile, and the strip's pages can only be clicked with the mouse (the tile can be reached with Tab). Picks are not kept when another comic is loaded. Extracting pages asks for a folder every time instead of using the *Save to* setting, which applies to the cover and the ZIP. Switching the picker's *Numbering* to *By page number* sorts the picks for good: switching back does not restore the order they were picked in.
- Python is required to run; a double-click `.exe` is planned.
